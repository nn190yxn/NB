# 风格派本地验收问题修复设计

- 日期：2026-09-04
- 作者：Monkeycode
- 状态：已获用户确认，待规格复核
- 项目：`E:\程序开发\NB\风格派个人IP内容平台`

## 1. 目标

修复本地浏览器验收中确认的四个前端问题：

1. 390px 移动端选题卡片正文被操作区挤成狭窄竖列；
2. 撤回确认后撤回原因不稳定或不可见；
3. 发布前检查直接展示 `passed`、`warning`、`blocked` 等英文状态；
4. 选题生成接口返回 422 或网络错误时，界面静默吞掉错误。

## 2. 范围与边界

只修改前端展示和交互，不改变服务端接口契约、数据库、生产配置或产品数据。

允许修改：

- `src/main.tsx`
- `src/styles.css`
- 与本次修复直接相关的专项验证文件
- 本规格及任务记录文件

不修改：

- `server/` 接口和数据结构
- 生产环境、部署凭据和数据库
- 与上述四个问题无关的页面、组件或视觉重构

## 3. 方案

采用局部前端修复，不建立全局通知系统。

### 3.1 选题卡片布局

沿用已确认的 A 方案：在移动断点下，选题卡片正文、评分/证据和操作区上下排列。操作按钮允许换行，不使用固定侧栏、不遮挡正文、不产生横向溢出。桌面和平板保持现有结构，必要时仅在现有响应式断点调整布局规则。

### 3.2 选题生成错误

复用现有 `apiJson` 请求封装，确保非 2xx 响应能保留服务端返回的 `error`、`missing_fields` 和状态码信息。

`generateTopics` 的交互规则：

- 请求开始时清空上一次错误并进入忙碌态；
- 422 且有服务端 `error` 时展示该中文原因；
- 若返回 `missing_fields`，将字段映射为“身份定位、服务对象、内容支柱”等中文名称并列出；
- 网络错误、5xx 或无法解析响应时展示“选题生成失败，请稍后重试。”；
- 错误容器使用 `role="alert"`，成功生成后清空错误。

### 3.3 撤回原因

在 `DraftApprovalPanel` 中，当 `approval.status === 'revoked'` 时：

- 第一行始终优先展示 `已撤回：{revoke_reason}`；
- 原因缺失时使用“已撤回：需要修改”；
- 第二行单独展示“修改后需重新完成检查并确认”；
- 不让发布清单或事实核验提示覆盖撤回原因。

### 3.4 检查状态中文化

建立前端展示映射：

- `passed` → `已通过`
- `warning` → `有提醒`
- `blocked` → `未通过`
- 空值、版本不匹配或未执行 → `待检查`

映射只改变展示文案，不改变服务端状态值、CSS 状态类或状态判断逻辑。检查结果中的证据和建议保持原样。

## 4. 数据流

```text
点击生成
  → 清空错误并设置 busy
  → 读取研究与素材
  → POST /api/topics/generate
  → 成功：更新 topics，清空错误
  → 422：展示服务端原因和缺失字段
  → 网络/5xx：展示通用重试提示

撤回 API 返回 draft
  → 更新 drafts
  → approval.status=revoked
  → 卡片优先展示 revoke_reason

读取 draft.checks
  → 保留原始 status 做判断
  → 使用中文映射做展示
```

## 5. 测试与验收

### 5.1 自动检查

运行：

```text
npm test
npm run typecheck
npm run build
```

如新增专项测试，先运行专项测试，再运行上述完整检查。

### 5.2 浏览器验收

在本地 Chrome/CDP 环境验证：

- 390px：选题正文、评分证据和操作区上下排列；正文不被挤成窄列；无横向溢出；
- 选题生成缺少来源时：页面显示“选题生成至少需要一个有效来源”；
- IP 档案不足时：页面显示服务端原因和缺失字段中文名；
- 网络或 5xx 失败时：页面显示通用重试提示；
- 人设、质量门、发布清单状态只显示中文业务文案；
- 撤回后第一行显示实际撤回原因，第二行显示重新检查提示。

### 5.3 成功标准

四个问题均能在本地复现并验证修复；现有测试、类型检查和构建无回归；没有生产环境操作或数据迁移。

## 6. 风险与取舍

- `apiJson` 若扩展错误信息解析，必须保持成功响应和现有调用方不变；若现有封装已能提供错误对象，则只补充类型和页面处理。
- 中文状态只影响可见文案，不能把英文状态值改写后再提交 API。
- 移动端只调整选题卡片布局，避免波及内容创作草稿卡片。
- 复杂的全局 Toast、服务端错误码体系和新的弹窗交互不在本次范围内。
