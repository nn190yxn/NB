# 第一批可靠保存修复设计

作者：Monkeycode

日期：2026-09-07

## 范围

用户已确认优先修复配置持久化、访谈保存与续填、未保存草稿保护。仅本地修改和验证，不部署、不提交、不读取生产凭据或用户数据。不修改定位生成算法、页面视觉、历史选题、桌面登录及复盘指标。

## 方案

沿用现有接口和 MySQL 通用集合/用户文档结构，不增加新表或全局状态框架。替代方案为新建独立引导服务、重构存储层，因改动较大且非必要暂不采用。

### 配置持久化

将 api_configs 注册进 collectionNames，使现有 saveState 调用进入通用集合保存路径。现有表支持该集合，无需改表。保留密文及账号所有权，不输出配置值。测试覆盖白名单、集合写入、重新加载及跨账号隔离；模拟池测试不能冒充真实 MySQL 重启验收。已因历史缺陷遗失的配置无法凭空恢复。

### 访谈保存与续填

使用现有账号 positioning 文档存储下一步进度，复用 interview_answers 和目标字段。初始化先加载文档，成功前禁用回答提交。历史文档无进度时根据已存在答案推导首个未答步骤；已完成文档进入结果流程的兼容行为需保持明确，不自动修改历史答案。

继续、跳过及稍后填写均等待保存结果；保存中禁止重复操作。失败保留当前输入、步骤及错误提示，允许重试。成功后再清空当前输入或退出。记录稍后填写标记仍属于账号文档，不使用浏览器标记。

最后一题保存成功才进入候选生成，保留目标值供结果摘要显示。候选算法与档案同步属于下一批，不在本批重写。刷新只能恢复已成功保存的内容，未保存文字需离开提醒，不承诺断电恢复。

### 草稿保护

已有 dirtyDrafts 作为脏状态来源；未保存时禁用会以服务端返回值替换正文的 Hook、检查、恢复、改写替换等动作，提示先保存。保存请求失败保留输入与脏状态，显示错误，成功才移除脏状态；请求期间阻止重复保存及编辑产生响应覆盖。

离开创作到其他页面、打开会导致组件卸载的引导或注销时，存在脏稿则确认放弃。刷新/关闭使用 beforeunload 原生提醒；不引入自动保存或离线持久化，也不宣称浏览器一定显示提醒。

## 验收

- 配置集合经保存后重新加载仍有密文记录且账号隔离。
- 访谈加载/保存失败不跳步、不清空输入、不显示成功。
- 回到访谈恢复已保存步骤和答案；最后一题无保存/生成竞态且目标摘要正确。
- 草稿未保存时覆盖性动作不能执行；失败仍可重试；离开有提醒。
- 针对性回归、类型检查、构建及 diff 格式检查通过。浏览器无法执行时明确记录未验证项。
