# 风格派内容资产跨端闭环设计

- 日期：2026-09-01
- 作者：Monkeycode
- 状态：设计已确认，待用户审阅后进入实施计划

## 1. 目标

建立三条可追溯的内容资产链路：

1. 热点研究结果经用户确认后进入素材库。
2. Windows Electron 桌面端持续同步本地文件夹到素材库。
3. 手机打开今日待拍文案，并上传后台截图或数据，经过专用视觉模型解析、人工确认后写入内容表现快照。

网页/移动端与 Electron 并存：网页和手机负责跨设备使用，Electron 负责 Windows 本地文件夹持续同步和重度资产管理。

## 2. 范围与顺序

### 阶段一：热点研究到素材库

- 热点搜索结果提供“收录为素材”。
- 仅用户主动收录，搜索结果不自动污染素材库。
- 生成 `hotspot` 素材，保存标题、平台、原链接、热度、研究记录 ID、收录时间。
- 重复收录返回已有记录，不创建副本。
- 研究记录和分析报告继续保留在热点研究。

### 阶段二：Electron 文件夹同步

- Windows Electron 应用，支持登录现有账号。
- 添加、暂停、恢复、移除一个或多个本地同步文件夹。
- 持续监听新增和修改文件。
- 首版支持 TXT、Markdown、Word、PDF、Excel。
- 二进制安全上传，由服务端统一解析。
- 本地删除仅标记“源文件已删除”，不删除云端素材。
- 展示同步队列、失败原因、重试和去重状态。

### 阶段三：手机数据上传与解析

- 今日待拍文案支持标记为已发布。
- 手机上传一张或多张运营后台截图，也支持上传数据文件。
- 使用 API 3 专用视觉模型识别平台、指标名称、数值和对应关系。
- 系统提出匹配文案候选，不确定时进入待匹配列表。
- 用户确认或修正后生成内容表现快照，不覆盖历史数据。
- API 3 未配置或失败时支持手动录入。

## 3. 三 API 职责

### API 1：主文本模型

用于选题生成、文案生成、文本分析和文本结构化。

### API 2：备用文本模型

与 API 1 使用相同文本接口；API 1 失败、超时或限流时自动接管。

### API 3：专用视觉模型

仅用于截图和图片理解：平台识别、页面理解、指标与数字对应、多图合并解析和结构化候选结果。

图片任务只调用 API 3，不把图片转发给 API 1 或 API 2。

## 4. 配置与安全

三套 API 配置按账号加密保存于服务端，网页、手机和 Electron 共用。

- 服务端使用环境变量中的主密钥进行 AES-256-GCM 加密。
- 数据库存储密文、随机 IV 和认证标签。
- 前端仅返回掩码，不返回明文 Key。
- 修改 Key 必须重新输入完整值。
- API 1、API 2、API 3 分别测试连接、启用或停用。
- 旧浏览器本地配置不自动上传，首次迁移需用户确认。
- 日志、错误响应和素材记录不得包含明文 Key。

## 5. 统一数据模型

### 素材

```text
material
├─ material_kind: article | quote | hotspot | insight | experience
├─ source_type: research | local_sync | mobile_upload | manual
├─ source_id
├─ source_path
├─ device_id
├─ checksum
├─ source_deleted_at
├─ parse_status: pending | processing | ready | failed
└─ review_status: pending | approved | rejected
```

### Electron 同步

保存设备、同步文件夹、同步文件三层记录：

- 设备：设备 ID、名称、最后在线时间。
- 文件夹：本地路径、启用状态、最后扫描时间。
- 文件：相对路径、校验值、修改时间、同步状态、对应素材 ID。

服务端以“账号 + 文件路径 + 校验值”识别新增、修改和重复。

### 内容表现

```text
performance_snapshot
├─ draft_id / shooting_id
├─ platform
├─ published_at
├─ captured_at
├─ metrics
├─ screenshot_file_id
├─ raw_model_result
├─ confidence
├─ status: pending_confirmation | confirmed | rejected
└─ corrected_fields
```

缺失指标保持空值，不将缺失数据编造成零。每次确认创建新快照。

## 6. 数据流

```text
热点研究 → 用户收录 → hotspot 素材
本地文件夹 → Electron → 服务端解析 → 素材库
手机截图 → API 3 → 候选指标 → 用户确认 → 表现快照
```

原始文档、截图和模型原始结果保留受控引用；文件下载和预览必须经过登录鉴权。文件名清洗，禁止路径穿越，限制类型和大小，并按校验值去重。

## 7. 异常处理

### Electron

- 文件写入未完成：等待文件稳定。
- 快速连续修改：合并为最后一次事件。
- 断网：队列落盘，恢复后继续。
- 登录失效：暂停同步，不丢队列。
- 不支持或过大文件：不上传并显示原因。
- 重复文件：关联已有素材。
- 本地删除：保留云端素材并记录源文件删除时间。

### 手机解析

- 原始截图、原始模型结果和状态全部保留。
- 低置信度字段突出显示。
- 无法匹配文案时进入待匹配。
- API 3 失败可重试或手动填写。
- 用户确认前不得写入正式指标。

## 8. 验收标准

- 热点可收录、可追溯、可去重，未收录结果不进入素材库。
- Electron 在 Windows 可安装、登录、管理多个文件夹，并完成新增、修改、断网恢复和重复文件测试。
- 五类文档均能安全上传和正确解析。
- 手机可打开今日待拍文案并上传截图。
- API 3 能输出结构化候选结果，用户确认后才生成快照。
- API 1 失败时 API 2 接管；图片任务只走 API 3。
- 三套 Key 跨设备可用，但前端、日志和数据库查询接口不泄露明文。
- 保留原有素材、研究、草稿和拍摄清单行为。

## 9. 非目标

- 本期不做完全桌面化，不停止网页和移动入口。
- 不把所有热点搜索结果自动导入素材库。
- 不以本地删除直接删除云端素材。
- 不让模型结果绕过人工确认直接覆盖内容表现数据。
- 不把 API 1/API 2 当作视觉模型使用。
