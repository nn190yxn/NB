# Windows 本地一键启动设计

- 日期：2026-09-06
- 作者：Monkeycode

- 项目：`E:\程序开发\NB\风格派个人IP内容平台`

## 1. 目标

为 Windows 本地开发提供一个可双击执行的一键启动入口，同时启动 API 与 Vite 前端，隐藏运行窗口，把输出合并到一个日志文件，并在页面可访问后自动打开浏览器。

## 2. 范围与边界

新增：

- `一键启动.bat`：用户双击入口；
- `scripts/start-local.mjs`：服务检查、进程启动、日志合并和浏览器打开逻辑；
- `.monkeycode/specs/windows-one-click-start/README.md`：使用和维护说明。

修改：

- `.gitignore`：忽略运行日志和启动状态文件；
- 根目录 `README.md`：补充 Windows 一键启动方式。

不包含：

- 自动安装依赖；
- 自动停止服务；
- 修改 API、数据库或生产配置；
- 使用生产凭据或连接生产环境。

## 3. 启动流程

1. `一键启动.bat` 将工作目录切换到脚本所在项目根目录。
2. BAT 使用 PowerShell 的 `Start-Process` 隐藏启动 `node scripts/start-local.mjs`，随后立即退出。
3. Node 启动器检查 Node/npm 和项目依赖是否可用。
4. 检查 `127.0.0.1:3001` 与 `127.0.0.1:5173`：
   - 端口已响应时复用现有服务；
   - 未响应时分别启动 `npm run server` 与 `npm run dev -- --host 127.0.0.1`。
5. 两个子进程的标准输出和错误输出统一追加到根目录 `local-app.log`，每次启动写入带时间戳的分隔行。
6. 轮询 `http://127.0.0.1:5173/`，就绪后使用系统默认浏览器打开该地址。
7. 启动失败或等待超时时，仅写入日志并退出，不反复重启。

## 4. 重复启动与生命周期

- 重复双击不会再次占用已响应的端口。
- 如果两个端口均已响应，只打开浏览器并记录复用状态。
- 启动器退出后，API 与前端继续独立运行。
- 本任务不提供关闭按钮；关闭服务可通过任务管理器或另行增加停止脚本。
- 只判断目标端口是否能建立本地连接，不终止占用端口的既有进程。

## 5. 错误处理

- 缺少 Node/npm：写入明确错误，并通过短暂可见提示告知查看 `local-app.log`。
- 缺少 `node_modules`：提示先运行 `npm install`，不自动联网安装。
- 端口被非目标服务占用：记录健康检查失败和端口状态，不结束该进程。
- 子进程提前退出：记录退出码。
- 前端在限定检查次数内未就绪：记录超时，不打开浏览器。

日志不记录环境变量值、密码、API Key 或私钥内容。

## 6. 验收标准

1. 双击 `一键启动.bat` 后窗口立即退出，不保留 API/Vite 命令窗口。
2. API 在 3001 端口响应，前端在 5173 端口响应。
3. 默认浏览器自动打开 `http://127.0.0.1:5173/`。
4. `local-app.log` 同时包含 API、前端及启动器日志。
5. 再次双击不产生端口冲突，能复用已有服务并再次打开页面。
6. 缺少依赖时不崩溃、不自动安装，日志给出可操作提示。
7. `npm run verify` 继续通过。

## 7. 安全与兼容性

- 仅支持当前 Windows 开发环境。
- 子进程通过参数数组启动，不拼接用户输入，避免命令注入。
- 仅访问本机回环地址，不读取生产部署凭据。
- BAT 和 Node 启动器均以项目自身路径为基准，可从任意当前目录双击运行。
