# 红狐官网 API 真实接口接入设计

作者: Monkeycode

## 背景

当前项目此前按假定的 `/v1/*` 路径调用 RedFox，实际官网接口使用统一 Host `https://redfox.hk`，各能力由不同的 API Path、HTTP Method、请求体和响应结构定义。因此连接测试出现“返回了无效数据”。

## 目标

将现有红狐研究能力切换到官网公开 API，同时保留账号级服务端 AES-256-GCM 加密、前端不携带明文 Key、账号隔离和无配置演示数据兜底。

## 方案

### 配置与数据流

浏览器只提交 Base URL 和完整 Key 到本地服务端保存；服务端解密当前账号配置后调用 RedFox，归一化响应，再返回工作台所需结构。公开配置只返回 Base URL、Key 掩码和更新时间。

默认 Base URL 为 `https://redfox.hk`。浏览器和研究请求不再传递 `x-redfox-api-key`。

### 官网接口映射

| 工作台能力 | Method | 官网 Path |
|---|---:|---|
| 全网聚合热点 TOP10 | POST | `/story/api/hotKeyword/list` |
| 全网关键词热搜 | POST | `/story/api/hotSpot/getListByPlatformWithKeyword` |
| 小红书热门账号推荐 | POST | `/story/api/xhsData/query` |
| 小红书关键词搜索 | POST | 采用官网小红书 API 文档对应的搜索接口 |
| 多平台违禁词检测 | POST | 采用官网多平台/工具 API 文档对应接口 |

官网鉴权支持 `REDFOX_API_KEY` 或 `X-API-KEY` 请求头，JSON 请求使用 `Content-Type: application/json`。成功响应按 `{ code: 2000, data: ... }` 处理。

### 连接测试

连接测试调用官网已确认存在的聚合热点接口，不再请求不存在的 `/v1/trending`。测试只验证网络、鉴权、成功码和额度/频率错误，不向用户输出 Key，也不默认触发完整研究链路。

### 响应与错误

适配器负责将官网字段归一化为现有工作台结构；保留官网 `code`、安全错误分类和请求追踪信息。HTML、空响应、非 JSON 响应不得被误报为成功，需返回“接口路径或响应格式不正确”等可行动错误。上游错误只显示状态/错误信息，不显示鉴权值。

### 兼容性

无配置继续使用演示数据；正式内容研究仍要求配置启用。旧账号配置迁移和服务端加密逻辑保持不变。

## 验收标准

1. 研究和测试链路不再请求 `/v1/*`。
2. 官网接口按文档使用正确 Method、Path、鉴权头和请求体。
3. 成功响应 `code: 2000` 可归一化到现有页面结构。
4. Key 禁用、额度不足、频率限制、非 JSON 和错误路径均有明确错误。
5. 自动化测试覆盖接口映射、请求体、响应归一化、错误处理、账号隔离和敏感信息不泄露。
6. 前端构建通过，现有 129 项回归测试不退化。
7. 真实供应商调用仅在用户使用自己的新 Key 点击测试时执行；不自动触发付费研究调用。

## 当前限制

官网公开页面已确认 Host、鉴权方式、成功码以及部分接口路径；小红书搜索和违禁词接口的精确请求体/响应字段需在实施阶段逐项从官网 API 文档读取，不凭猜测实现。
