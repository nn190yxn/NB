# 内测额度与配置安全修复设计

## 背景

当前内测规模不超过 10 人。审查确认以下问题：共享 AI 额度耗尽后复盘和平台适配报错；仅配置备用模型可以绕过共享主模型额度；本地违禁词检查错误消耗红狐额度；README 对当前测试、认证、RedFox 与记忆提炼状态描述过期；生产加密主密钥缺失时会使用固定默认值。

本轮采用最小可靠修复，不引入分布式额度服务，不修改数据库结构，不迁移用户数据，不部署生产环境。

## 目标

1. 共享 AI 额度耗尽后，复盘和平台适配自动使用确定性规则，不返回通用请求错误。
2. 只有实际完全使用自有文本模型的账号才豁免共享 AI 额度。
3. 本地违禁词检查不消耗红狐额度，也不调用红狐上游。
4. 增加回归测试，覆盖上述三条此前遗漏的路径。
5. README 与当前实现保持一致，并明确生产必须配置 `API_CONFIG_ENCRYPTION_KEY`。

## 非目标

- 不修改生产环境变量。
- 不改变生产启动策略；缺少加密主密钥时本轮不阻止启动。
- 不重构 MySQL 存储模型。
- 不实现多实例原子额度计数。
- 不修改现有额度数值、北京时间重置规则或用户数据。

## 实现设计

### 1. AI 额度判断

新增一个小型判断函数，以本次调用实际形成的主备配置为输入：

- 主模型来自账号配置：不因共享主模型计费。
- 主模型来自项目共享配置：调用前检查并消耗共享额度。
- 仅配置账号备用模型，但主模型仍来自项目共享配置：仍然计费。
- 没有可用共享主模型：不计共享额度。

保留现有 `runtimeConfig` 的主备调用顺序，不修改 LLM 请求协议。

### 2. 额度耗尽降级

复盘和平台适配的“是否调用 LLM”变量改为可变状态。额度不足时只关闭 LLM 路径，继续执行现有确定性规则：

- 复盘使用 `retrospectDeterministic`。
- 平台适配使用 `deterministicAdaptation`。

`memories/extract` 和 `drafts/:id/deai` 没有确定性替代能力，额度不足时继续返回 429。

### 3. 本地违禁词检查

`drafts/:id/compliance` 直接调用适配器的本地 `prohibitedCheck`，不经过统一的 RedFox 远程调用计费包装。接口响应结构保持不变，`source` 继续为 `builtin`。

### 4. 文档同步

更新 README 中以下过期信息：

- 当前测试数量和质量门状态。
- 当前账号认证方式。
- RedFox 官方接口能力以及本地违禁词检查。
- 记忆自动提炼已经接通 LLM。
- 前端不再通过请求头携带明文 RedFox Key。
- 生产环境必须配置随机的 32 字节 `API_CONFIG_ENCRYPTION_KEY`；同时明确当前代码仍保留固定默认值，因此上线前必须由部署检查保证配置存在。

历史过程继续保留在 CHANGELOG，不改写历史条目。

## 测试设计

增加以下服务端回归测试：

1. AI 额度达到上限后调用复盘，返回 200 且结果来自确定性规则。
2. AI 额度达到上限后调用平台适配，返回 200 且生成规则适配结果。
3. 用户只配置自有备用模型时，主模型共享调用仍计入额度，达到上限后受限或降级。
4. 使用共享 RedFox 配置执行违禁词检查前后，红狐用量不变且上游命中数不增加。
5. 自有主模型用户继续不消耗共享 AI 额度。

完成后运行相关测试、完整 `npm run verify` 和 `git diff --check`。

## 验收标准

- 三个额度相关缺陷均有可复现且通过的回归测试。
- 原有测试全部通过。
- TypeScript 检查和生产构建通过。
- 不读取日志、凭据或生产数据。
- 不提交、不推送、不部署。
