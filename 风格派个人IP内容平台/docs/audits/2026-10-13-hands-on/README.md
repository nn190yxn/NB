## 二、对甲方两条问题的直接回答

### 问题一：生成的文案字很小

不是错觉，是两个真缺陷叠在一起。

**1. 正文框的字号行距规则写错了，浏览器直接忽略了整条。**

`src/styles.css` 里 `.draft-body-input` 有三条规则：

```css
.draft-title-input, .draft-body-input { ... font: 600 16px var(--font-heading); }
.draft-body-input { min-height: 145px; resize: vertical; font: 13.5px/1.75 inherit; }
.draft-body-input { min-height: 320px; }
```

第二条想说的是「正文用 13.5px、行距 1.75」，但 CSS 的 `font` 简写里不允许出现 `inherit`，
整条声明作废。作废之后，正文退回用第一条：标题字体（Noto Serif SC）的 **16px 半粗体**，
行距是浏览器默认（约 1.15）。

在页面里实测计算值：

| 项 | 现在实际 | 设计想要的 | 临时改成正确写法 |
|---|---|---|---|
| 字号 | 16px | 13.5px | 13.5px |
| 字重 | 600（半粗） | 常规 | 400 |
| 行距 | normal（约 1.15） | 1.75 | 23.6px |

所以看着「又黑又挤」，这不是屏幕问题。

**2. 正文框高度写死 320px，不跟稿子长度走。**

320px 约等于 16 到 17 行。按当前正文宽度算，一屏能看的字数大约：

| 稿子 | 字数 | 一屏能看到 |
|---|---|---|
| 视频号长视频文字稿 | 429 | 基本能看全（实测 scrollHeight 345 / clientHeight 318，差 8%） |
| 长视频 1500 字目标 | 1500 | 约六成 |
| 公众号版实测最长 | 3657 | 约两成 |

**3. 顺带量到的：内容创作页有 38% 的文字在 11px 及以下。**

用视口 651px 逐节点统计可见文字：

| 页面 | 可见文字条数 | 小于等于 11px | 占比 |
|---|---|---|---|
| 内容创作 | 226 | 86 | 38% |
| 选题助手 | 161 | 28 | 17% |
| 素材库 | 85 | 6 | 7% |
| 今日工作台 | 79 | 1 | 1% |

内容创作页的字号分布：10px×15、10.5px×32、11px×39、11.5px×28、12.5px×65。
全项目字号都是写死的 px，没有响应式，也没有最小字号下限，手机端一样是 10.5px。
README 设计规范里写的阶梯是「次要文字最低 11.5px」，实际有 10 和 10.5 两档在设计规范之外。

### 问题二：AI 味很明显

这一条更严重：我们做了很久的「去 AI 化」，检测层其实只看着表面几个词。

**1. 22 条特征里，在你自己的稿子真响过的只有 3 条。**

把副本里 41 份草稿全扫一遍（用的是工作台自己的判据，不是外接模型）：

- 总命中 118 次，平均每份 2.9 次，41 份里只有 1 份零命中。
- 按命中次数排：设问开头 23 份、「不是 X 是 Y」22 份、来路不明的经历数量 19 份、
  具体案例或数字 13 份、咨询腔 8 份、串平台 2 份（8 次）、讲方法骨架 3 份。
- 但这些命中按 dbs 那 22 条特征归口，只覆盖到 3 条：「不是 X 是 Y」高密度、中文翻译腔、
  连接词过度使用。剩下 19 条在你的真实稿子里一次都没响过。

**2. 那 19 条不是「你的稿子恰好没这个毛病」，大部分是规则太窄，基本响不了。**

给每条都喂了一段明知犯样的文本做探针，21 条测试里 17 条不响。看实现就知道为什么：

| 特征 | 检测规则实际长什么样 |
|---|---|
| 精确到不真实的情绪细节 | 只匹配 `\d+\.\d+秒`，也就是书里举例那个「1.7 秒」 |
| 用身体感受替代论证 | 只匹配「身体知道答案」这一句原话 |
| 同义词刻意替换 | 只匹配「或者说 / 也可以叫 / 换个说法」三个连接词；真换同义词不会带这几个词 |
| 堵住所有反驳 | 要 9 个固定话术里出现 2 个（「你可能会说」「别急着反驳」……） |
| 给概念起名字的仪式 | 要同一个句式出现 2 次（「我称之为」×2） |
| 没有任何犹豫 | 要 5 个词里出现 2 个（「毫无疑问」「百分百」……） |
| 把结论包装成协议 | 只匹配「记住这几条」「三条军规」「当成协议」 |
| 句子节奏过于均匀 | 只取前 5 个句子，字数极差 ≤4 才算 |

每条都各有一条正向单元测试，测试用的正是那几个字面例子。所以测试全绿和真响得住，
在这一层是两件不同的事。

**3. 检查面板把最该看的东西折起来了，还贴错了标签。**

以那份 429 字的稿子为例，界面上是：

```
质量门  已通过（2 条提醒）  80 分
  ├ 尚未用「开头句」槽位确定开头范式
  └ 正文 429 字，视频号长视频目标 600-1500 字
  ▸ 语言层 22 特征：命中 8 处 · 视为可选，点开看
```

露在外面的两条都不是 AI 味。AI 味藏在折叠里，标题写着「22 特征」，展开后 8 条中有 6 条
其实是结构层的长句判据（「这句 38 字，一口气念不完」），真正的 22 特征只有 1 条。
「视为可选」这个措辞也会让人以为可以不管。

最后一条的文案是拼接坏的，直接给用户看了内部标签，同一句引用重复了两遍：

```
中信号 来路不明的经历数量
正文出现自己的经历数量：第一人称经历｜我们常说要构建个人IP，但很多人陷入了一个误区：
把内容当成作品，而不是产品正文出现自己的经历数量：第一人称经历｜……、重复次数｜我见过很多老板……
```

另外，同一屏里人设检查给 100 分、质量门给 80 分。这段正文里就有「我见过很多老板」和
「构建个人IP」，人设检查照样满分通过。两个分数并排放着，使用者不知道信哪个。

**4. 「改成你自己的说法」改了节奏，没改掉毛病的根。**

拿这份稿子真跑一次改写（沙箱，1 次模型调用，出 420 字）：

| 指标 | 改写前 | 改写后 | |
|---|---|---|---|
| 平均句长 | 28 字 | 25 字 | 改善 |
| 最长句 | 52 字 | 50 字 | 改善 |
| 段落数 | 1 | 14 | 变松了（这是好事，口播能换气） |
| 三连排比 | 1 | 0 | 改善 |
| 咨询腔词 | 6 | 5 | 略改善 |
| 借来的 dbs 金句 | 2 | 2 | 没变 |
| 「我见过很多/太多老板」 | 1 | 1 | 没变，而且「很多」被改成「太多」 |
| 结尾升华句 | 2 | 1 | 略改善 |
| 检测器命中数 | 2 | 2 | 没变 |

也就是说：句子被拆短了、分段了、口语词进来了，但让人一眼认出是 AI 写的三样东西原样留着
（借来的金句、编出来的案例、升华式收尾）。检测器前后命中数一样，系统自己也看不出这一版更好。

## 三、顺带查出来的两件事

**1. 素材库看着是空的，其实有 44 条被撤下来的东西回不去。**

副本数据里 `materials` 共 45 条，其中 44 条 `status: 'withdrawn'`（9 月 19 日清对标内容时撤的），
只有 1 条 `ready`。`GET /api/materials` 不返回 withdrawn，界面上既没有「已撤回」视图，
也没有恢复入口。对使用者来说：库里只剩 1 条，而他上周还在用的一批素材一个字没丢，就是找不回来。

**2. 首页同一屏有两张互相打脸的卡。**

路由卡说「这一条走到第 3/7 步，下一步：定稿」，下面紧跟一句「从你的定位开始，
完善 IP 档案后研究、选题和创作会更贴近你的真实目标」。定位档案明明已经有内容。

**3. 一件可能省掉重复劳动的事。**

规划文档里「阶段 11 标记式改稿」一直列为唯一未完成的核心项。但界面上的「定位替换」
已经是勾选式换句：列出原文和替换句，勾哪几条就只改那几句，其余不动，还会报「退回了 N 条」。
看起来这就是标记式改稿要做的事。开工前先确认它覆盖到什么程度，别把已经做好的东西再做一遍。

## 四、本轮建议的排期

按「你每天坐下来用得到」排序，不按工程难度。

| 顺位 | 做什么 | 为什么 |
|---|---|---|
| 1 | 正文框和字号：修掉那条失效的 CSS，正文给到 15px 以上、行距 1.8、字重常规；高度跟稿子长度走或给一个全宽阅读模式；把 10px 和 10.5px 并进 11.5px 以上，设一条字号下限 | 改动最小、天天生效，直接对上你说的「字很小」 |
| 2 | 语言层重做：从「关键词表」换成按句子结构算的判据（句子长短均匀度、每段是不是都收金句、翻转句式密度、抽象词占比），并先把长句那 6 条从「22 特征」标题里拆出来单独显示，拼接坏的那条文案当场修 | 现在这一层测的是「用没用某个词」，测不出毛病本身 |
| 3 | 去 AI 味改写的目标改成三条硬要求：不许保留借来的金句、不许留升华式收尾、不许新增编造案例；改写完自动重跑检测，把前后命中数并排显示 | 让你看得出「这次真的少了 3 处」，而不是只能靠感觉 |
| 4 | 素材库补「已撤回」视图和一键恢复 | 44 条素材回不来这件事，比库里东西少更麻烦 |
| 5 | 交付收尾：提交并推 9 月 21 日那一批、部署到 content.woyai.cn、重打桌面包、在 MySQL 模式下把这批新功能真跑一遍 | 现在线上还是 9 月 20 日的版本，改了你也看不到 |
