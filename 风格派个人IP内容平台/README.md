# 风格派个人IP内容平台（定位派内容工作台）

**作者：Monkeycode**

面向个人 IP 创作者的一站式内容工作台：定位发现、热点研究、素材管理、选题生成、多平台草稿、爆款方法、拍摄执行与 AI 记忆。Web 工作台 + 手机 PWA 双形态，支持七个内容平台（全平台/小红书/抖音/视频号/公众号/B站/微博/X）。

本文档面向所有后续接手本项目的开发者与 AI Agent，读完即可独立开展开发、验证与部署。

---

## 第 0 节：这个工作台以什么身份在做（后续所有开发先读这一节）

### 建设者的角色

**以自媒体操盘手、内容专家的身份建设这个工作台，不是工程师，也不是审计员。**

判断一件事该不该做的标准只有一条：**它能不能帮创作者把号做起来、赚到钱。** 技术上正确但不产生内容价值的东西，不加。

### 系统与创作者的关系（本项目最重要的一条约定）

DBS（dontbesilent，抖音 49.7 万粉，开源方法论 `dontbesilent2025/dbskill`）的做法是：以专业判断给出**审计意见**——"我认为这样做不对""建议你改成这样"——但**从不因为你不照做就拦住你**。它给的是智慧，不是许可。

这个工作台同理，这是一条硬边界：

| | |
|---|---|
| **可以做** | 给判断、给建议、给评分、给优化方向、在最后一步给一句提醒 |
| **不可以做** | 因为创作者没按建议做而拦住他；因为他还没录入而拦住他；把自己的标准当成发布许可 |

**门槛只设在"技术做不到"的事上：**

- **可以拦**：模型没配、网络断了、参数非法
- **不能拦**：还没录进来的、还没来得及整理的、还只在脑子里的东西
- **提醒的位置**：永远在最后一步，一句话，不设填写门槛
- **提醒的口吻**：同行提醒"你接得住吗"，不是审计问"凭证呢"

理由：要求创作者把三四十年的经历先录成数据库再发内容，是不可能的，也是反创作的。很多素材是复盘时才想起、某个场合突然想起的——**在你要建库那一刻它还不存在**。创作者对自己的数据负责；**系统既不是数据的负责人，也不是最后的审核人**。

### 三层流量的准确定义（决定每个环节怎么设计）

流量 = 对某个内容感兴趣的人。

| | 泛流量 | 精准流量 |
|---|---|---|
| 平台视角 | 推给"有宽泛相关兴趣"、被动接收推送的人 | 推给有明确需求的人 |
| 漏斗位置 | 入口最宽的那一段 | 接近终点的那一段 |
| 要拿到的东西 | **被看见**：播放、3 秒完播、互动 | **被行动**：关注、咨询、下单 |
| 靠什么奏效 | **情绪**：强情绪、紧节奏、有反转、有互动 | 专业、可信、可核验 |
| 核心指标 | 3 秒完播率、互动率 | 收藏、私信、转化 |

**两个必须记住的纠偏：**

1. **泛流量与精准流量的区别不在流量大小**，而在**中间有没有环节把人甩掉**。所以泛流量内容不是"做得浅一点的内容"，它是**另一种活**——靠情绪把人按住，而不是靠信息把人说服。
2. 泛流量内容最常见的死因是**选题过窄**——只讲自己的专业领域，却指望陌生人对你的专业产生兴趣。

### 三层对应的内容写法

| | 泛流量触达 | 垂直信任 | 核心目标转化 |
|---|---|---|---|
| 内容主语 | **他**（观众） | 这件事 | 你和他的下一步 |
| 开局任务 | 3 秒内让他对号入座 | 说出他形容不出的那个词 | 说清给谁、给什么、多久见效 |
| 中段任务 | 情绪推进：期待 → 反转 → 共鸣 | 逻辑链 + 给边界 | 真实过程 + 可核验结果 + 主动说不适合谁 |
| 收尾任务 | 不收束，留缺口 | 给判断标准，让他收藏 | 明确下一步 + 降门槛 |
| 最常犯的错 | 讲方法论、上清单 SOP | 纯情绪、纯故事 | 不点名的暗示成交 |

### 当前已知的落地状态

策略卡上的三条比例（`layer_ratios`：泛流量／垂直信任／核心转化）**已经接上生成环节**（2026-09-19，阶段 1「通电」）：

- **选题生成**：`server/layer-ledger.mjs` 按 `review_period`（ISO 8601 时长，默认 `P14D`）算出本期各层已出条数与配比的欠额，欠额写进选题生成的提示词（`server/index.mjs` 的 `POST /api/topics/generate`），并作为 `generation_context.layer_ledger` 随选题落库。选题同时落 `created_at`；没有这个字段的老选题按「本期之前」读，不计进本期的账，也不影响可用性。
- **草稿写法**：`strategy_layer` 进草稿生成提示词（`draftBriefPrompt` 第三个参数），三层各有一套侧重（`strategyLayerWriting`）——触达层调开头留人，信任层调中段给做法与证据，转化层调结尾落到一步。不传层级时退回原样，向后兼容。
- **仍然没接通的**：`layer_metrics` 与周期复盘（`POST /api/content-strategy/reviews` 仍恒返回 `insufficient_data`）；配比也不影响平台选择与发布节奏。

素材库已分两池（2026-09-19，阶段 2「料台」）：

- **热点素材**：搜进来的热点和资讯（`material_kind === 'hotspot'` 的新建自动带 `expires_at`），默认 **30 天保鲜期**，过期自动沉底——不删，只是不再挡在眼前。
- **自建素材**：你的经历、案例、客户原话，没有 `expires_at`，永不过期。
- **分池依据只有「会不会过期」这一个**，不另存一个 `material_pool` 字段——存了就会和 `expires_at` 打架。因此老素材（全库无这两个字段）读出来自然就是「自建池 + 用途签留空」，**不需要任何数据迁移**。
- 用途签 `use_tag`：`pierce`（戳人的）/ `proof`（证明的），不填也能存，可用 `PATCH /api/materials/:id` 改或撤。
- 列表接口每条素材带 `material_pool` / `days_left` / `expired` / `use_tag`，并支持 `?pool=hot|built` 筛选；首页三个数（没过期的热点数 + 最快过期天数 / 戳人的 / 证明的）挂在 `GET /api/materials?kind_counts=1` 响应的 `pool_summary` 里，已排除过期与已撤回的。
- 实现集中在 `server/material-pools.mjs` 与 `src/main.tsx` 的 `MaterialWorkspace`；原型为 `mockups/素材库-新料台.html`。

选题入口可以点名（2026-09-19，阶段 2 第二半，`server/topic-hooks.mjs`）：

- `POST /api/topics/generate` 接受两个**可选**参数：`strategy_layer`（`reach`/`trust`/`conversion`）与 `hook_kind`（四类钩子：`counter_consensus` 打翻共识 / `contrast_number` 反差数字 / `identity` 身份代入 / `public_emotion` 公共情绪）。

## 三个加工面板改成左输入右结果，并补上漏写的多行框样式（2026-09-19）

Alex 发了一张提主张的截图说「页面需要调整下，美观一些」。看下来是四件事，前三件是客观缺陷，第四件才是审美。全量 374 / 374 通过（新增 1 条前端静态断言），并在真实浏览器里逐页看了一遍。

### ① 多行输入框的样式漏写（截图里那个小框）

`styles.css` 给输入框写了完整框样式，但**只写了 `input`**：

```css
.deconstruct-input input { width: 100%; padding: 11px 14px; border: 1px solid var(--line); ... }
.deconstruct-input textarea { min-height: 96px; resize: vertical; line-height: 1.7; }   /* ← 没有宽度、内边距、边框、背景 */
```

textarea 退回浏览器默认尺寸（默认 20 字符宽，正好是截图里那个约 260px 的窄框）。拆概念那边看不出来，是因为它的多行框用了另一个带样式的类；**这是项目里唯一一条不完整的多行框样式**，引导问卷 / 档案编辑 / 素材原子 / 草稿改写 / 反馈都写全了。

### ②③ 下拉框拉满页宽、空状态是个大坑

- 「从素材库选一条」原来是全宽控件（1700px），看着像标题不像控件。项目里同类控件（`atom-mini-form select`）是紧凑的。
- `.structure-empty` 写死 `padding: 38px` 居中，一行字占近 180px 高。

### ④ 按钮离它作用的输入框隔一个页宽

三处主按钮原本留在标题行右上角，跟它要作用的输入框一个在页面最右、一个在页面最左。

### 改法：左输入、右结果两栏

新增 `.workspace-split`（`grid-template-columns: minmax(0, 1fr) minmax(0, 1.08fr)`），**沿用草稿工作台已有的 1100px 折叠线**，没有另立一套断点。左栏是输入 + 跟着输入走的按钮行，右栏是结果 / 空状态。

| 文件 | 改动 |
|---|---|
| `styles.css` | 补全 `.deconstruct-input textarea`；新增 `.workspace-split` / `.workspace-pane` / `.workspace-pane-actions`，1100px 折叠、680px 收窄 |

## 三步之间能带得进、带得走：判完的形式不再白判（2026-09-19）

拆概念 / 提主张 / 形式判断是内容加工的三个入口。实际用下来暴露四个问题，根子是同一个：**每一步都是孤岛——输入只能手打手粘，产出不记来源。** 全量 373 / 373 通过（新增 4 条服务端测试 + 2 条前端静态断言）。

### ① 形式判断判完没有归宿（硬断链）

面板自己写着「先定形式再动笔，别按错的形式写完才返工」，但**判了等于没判**：

- 生成草稿的界面上**没有任何地方能传形式**；
- 服务端 `content_format` 写死 `defaultContentFormat(platform)`——抖音 / 视频号一律「短视频」；
- 生成提示词两处直接写死「短视频口播（约 1-3 分钟，300-900 字）」，模型只会写短视频；
- 唯一能改的地方是草稿生成后点体裁按钮，**那会再调一次模型重写这一条**。

所以「别返工」的路径本身就是「必然返工一次」。

改法：

| 位置 | 改动 |
|---|---|
| `draft-writing.mjs` | 新增 `resolveVideoFormat(requested)`：只认 `draftVideoFormats` 里的三种，其余落回平台默认 |
| 同上 | `draftBriefPrompt(profile, format)` 与 `draftGateRewritePrompt(summary, format)` 按形式参数化，体裁说明与字数都取自该形式 |
| `buildDraftBrief` | 简报新增 `content_format`，模型看得到形式 |
| `index.mjs` `/api/drafts/generate` | 形式按 `body.content_format → topic.content_format → 平台默认` 解析，两条平台草稿写同一个形式 |

判完的形式存在**选题**上（`topic.content_format` / `content_format_reason`），生成时不用再手抄一遍。

### ②③ 输入只能手打，产出不记来源

- **提主张**：素材早就在库里，却要从素材库复制、切页面、粘进 8000 字的框。
- **拆概念 / 提主张的产出**：入库时只传正文和角色，**没传「来自哪条素材」**，所以列表上显示「来源：手动创建」。而服务端 `POST /api/materials/atoms` **本来就支持 `source_id`**（会写 `origin_source_id`、`source_refs`，并继承策略层与目标）——素材库的「收为素材」已经在传，只有这两个面板漏了。

改法：两个面板加共用的 `SourceMaterialSelect`（`useMaterialLibrary` 拉 `/api/materials`）。提主张选中即把正文填进输入框；拆概念选中即显示来源名、可点的候选词（取 `extracted_fields.candidate_topics`）与可折叠原文。确认入库时都带 `source_id`。

一个诚实的边界：**拆概念仍然是半自动**——素材里往往有好几个词，「拆哪个」是使用者的判断，系统只给候选词，不替他选。

### ④ 切页面就丢上下文

三个面板原本是 `if (section === …) return <Panel />`，切走即卸载，输入与提案全丢。改为三个保持挂载、切走只 `display:none`。布局层已验证：`.page-content` 是块级流、`.workspace-view` 只有 `margin-top`，包裹层不改变排版；`.compose-row` 本来就 `flex-wrap: wrap`，第三个下拉框会换行。

### 未改

- 形式只落在视频体裁上；`长文` 是形式判断的第四种，但不进抖音 / 视频号草稿，`resolveVideoFormat('长文')` 落回短视频。
- 形式判断的选题下拉列全部选题；生成仍只收「已确认」选题，未确认的选题判完会在确认后生效。
- `defaultContentFormat` 保留，作为两个提示词函数的默认值（默认落回短视频），既有测试的 300-900 字口径不变。
- 三个面板的工具函数（`useMaterialLibrary`）各拉一次素材列表，没有做跨面板缓存。

## 素材库只留创作者自己的素材，对标内容全部归位（2026-09-19）

## 检测器三处修复：盲区测试、矛盾判定、数字后门（2026-09-19）

用一条真实口播稿压测检测器，抽出三个结构性问题。全量 367 / 367 通过。

### ① 7 条特征有检测器、零 hit/miss 测试

22 条特征里，`golden_tail`、`generic_ending`、`connector_abuse`、`fake_rebuttal`、`triple_list`、`vague_case`、`consulting_tone` 这 7 条只有检测器，没有任何对照样本。

**证据是因果的**：上一条被发现的整类漏判（`ai_tone_phrase` 只认「不是…而是」）修复前就在这 7 条的同一种状态里。**没有 hit/miss 测试，检测器的盲区不会被发现。**

已补齐 7 条测试（每条都带一个必须命中、一个必须不命中的样本）。补测后 7 条检测器行为全部正确，没有发现新 bug。现在 22 / 22 都有对照。

### ②「首先/其次/再次」与「第一/第二/第三」被判出相反结论

同一个语域、同一个功能的序数连接词：

| 写法 | 修复前 |
|---|---|
| 第一 / 第二 / 第三 | 结构层免检 |
| 首先 / 其次 / 再次 | **3 条逻辑衔接跳跃** + 中文翻译腔 + 连接词滥用 |

同一段文本被判出互相矛盾的两个结论：结构层说「这里没有承接信号」，语言层说「连接词用太多」。

根因：结构层把**「词好不好」**和**「有没有衔接」**混在了一起——因为语言层把「首先」算翻译腔，结构层就反过来认定它不构成衔接。

修法：`transitionPattern` 补上 首先/其次/再次/此外/换句话说/更重要的是/总而言之/综上/总之。**结构层只判有没有衔接，用哪个词高不高级是语言层的事。**

### ③ 中文数字是闸门的后门

`dataNumberPattern` 用 `\d` 匹配，所以「播放八百」不算数据声明，而「播放 800」算。**它奖励了规避行为：把数字写成汉字就能绕过不可溯源闸门。**

修法分三处，缺一不可：

- `draftNumbers` 增加中文数字识别，沿用同一条规则（裸个位数是修辞，≥ 10 或带单位才是数据声明）；
- `unbackedNumberHits` 的**允许清单也换成同一套抽取逻辑**——原来只用 `\d` 抓素材里的数字，只改检测的话所有中文数字会必被判不可溯源；
- 两边**按数值归一化**再比，素材写 300、正文写三百算同一个数字。

误报防护：这是闸门，误报会直接拦住稿子。已排除成语（十分/百分/千万/万般/百般/十足/百姓）和估值（「几十条」「十几万」里的孤立「十」）。

**修复过程中自己踩的坑**：`vagueNeighbors.includes(text[index + length] || '')` 里，`'几数多来余许'.includes('')` 返回 `true`，导致**任何出现在文末的中文数字被静默跳过**。已显式判空。

### 没有做的一项

原计划的「转场词判据按体裁分」没有实施。实测发现 P0-2 修完后已经存在安全区：用口语连接词（其实/后来/所以/因为/说白了/接下来/问题是/因此）时，逻辑衔接和连接词滥用两层都是 0 命中。原来「写作者被夹在中间」的前提已经不成立，按最小必要原则不动。若以后发现图文稿被过度判跳跃，再按体裁分档。

## 去 AI 味检测：补齐「不是X，是Y」短式（2026-09-19）

口播稿几乎都省掉「而」，写成「不是X，是Y」。原来的正则只认 `/不是…而是/`，这一类会**整批漏判**。

修复方式：

- 新增短式收集 `flipShortHits`，与原来那四条第式分开；
- **按密度报，不按单次报**：源技能的误伤警告写着「一次是正常修辞」（鲁迅、李敖、罗翔都用），阈值是 800 字内 3 次以上。实现为 `max(3, ceil(字数 / 800 * 3))`，长文按同一密度换算；
- 带「而」的长式仍走原来的正则，不受密度阈值影响；
- 语言层只提醒不拦停，与原有行为一致。

实测：629 字的真实口播稿只有 2 处短式翻转，**低于阈值，修完仍不报**——卡住它的是密度，不是漏判。

## 核心领域模型

数据以 `collection` 为单位存储（JSON 模式为一个大对象，MySQL 模式按表分）：`research`（研究）、`materials`（素材）、`drafts`（草稿）、`structures`（爆款方法库的兼容存储）、`topics`（选题）、`memories`（AI 记忆）、`shooting`（拍摄清单）、`profile_reviews`（IP 档案审核）等。

**新增 collection 有两处必改**：`server/mysql.mjs` 的 `collectionNames` + `server/index.mjs` 的 state 初始化。漏掉后者会报 `owned() TypeError`。

### 素材原子化

素材分五类 `material_kind`：`article`（文章，历史数据默认）/ `quote`（金句）/ `hotspot`（热点）/ `insight`（洞察）/ `experience`（经历）。两种产生方式：从文章提取结果一键收录（`POST /api/materials/atoms`，按 `origin_source_id + origin_text` 去重，源素材 `extracted_fields.collected` 标记）或手动新建。删除原子会恢复源素材的 collected 标记。

### 组合创作

`POST /api/drafts/generate` 除 `topic_id` / `structure_id` 外支持 `quote_ids`、`experience_ids`，正文按 方法骨架 → 金句参考 → 经历素材 → 行动指引 组装，`source_refs` 保留全部来源链路。

### AI 记忆层

三类记忆 `type`：`style`（风格）/ `topic`（选题）/ `feedback`（反馈）。CRUD 见 `/api/memories`；active 状态的记忆会在草稿生成时注入"创作风格要求"段落。`POST /api/memories/extract` 使用账号自有或项目共享的主备大模型，从对话/访谈文本提炼记忆；没有可用模型时返回 422 `llm_not_configured`。记忆 `provider` 字段保留后续升级路径。

## 认证与密钥模型

- **生产账号制**：生产环境要求注册或登录后访问 `/api/*`；开发/测试保留免登录身份，设置 `PRODUCT_ACCESS_PASSWORD` 时继续兼容旧访问密码通道。
- **API 配置服务端加密**：大模型 API 1/API 2/API 3 按账号使用 `API_CONFIG_ENCRYPTION_KEY` 进行 AES-256-GCM 加密，前端只读取掩码；API 1/2 串行兜底，视觉任务只使用 API 3。旧浏览器配置只通过显式迁移接口导入。
- 生产拒绝演示会话；项目共享红狐和文本模型 Key 只从服务端环境变量读取，并受每账号每日额度限制。

```bash

tar -C dist -czf /tmp/dist.tar.gz .

# 服务器上解压到临时目录后 rsync -a --delete 进 dist/

# 3. 服务端有改动时，额外执行（否则线上仍是旧逻辑！）

# 4. 验证服务端新路由特征（curl 打新端点确认 200/预期响应）
```

生产必须配置随机的 32 字节十六进制或 Base64 `API_CONFIG_ENCRYPTION_KEY`。当前代码为开发兼容保留固定默认值，因此部署检查必须保证生产环境变量存在，禁止使用默认值保存用户 API Key。

**最大陷阱**：服务端变更后只部署 dist 忘了 scp + pm2 restart，前端已更新而后端仍旧代码，表现为"接口不存在/行为不对"。部署后必须用 curl 验证一个新路由的特征响应。

**PM2 环境变量残留**：修改环境变量后 `pm2 restart --update-env` 可能不生效，需 `pm2 delete content-ip-workbench` 后用完整命令重建：

```bash
pm2 start server/index.mjs --name content-ip-workbench \
  --node-args="--env-file=/home/ubuntu/content-ip-workbench/.env.production" --time
```

服务器是多项目共存环境：数据库、目录、PM2 服务、Nginx、crontab 均按项目隔离，严禁改动其他项目的配置。

```bash
# 可选：--base http://localhost:3002 换端口；--password <访问密码> 用于生产；--user <id> 指定 dev 用户
```

资料包 JSON 结构：

| 键 | 用途 | 进哪里 |
|---|---|---|
| `structures[]` | 可复制机制（结构 / 范式 / 句式 / 清单） | 方法库 |
| `memories[]` | 对标机制 | AI 记忆（强制 benchmark + 来源） |
| `atoms[]` | 只收**创作者自己的**素材 | 素材库 |
| `reference{}` | 对标原话与结论，仅研究留存 | **不导入**（导入器不读这个键） |

`structures[]` 的字段：title / steps / platform / content_type。`memories[]` 只用 `content`，不沿用包里的 `memory_type`（旧包把它写成 style/topic，会把对标机制误当成创作者本人的表达习惯）。

**对标内容不进素材库。** 素材库是创作者自己的料仓（自己收集的、火狐采的、为拍短视频攒的）。对标账号的金句、句式、结论与方法都不是他的素材：金句是别人的原话，直接引用等于把人引向别人、改写则有洗稿风险；句式与方法本来就属于方法库。所以本项目的资料包 `atoms[]` 为空，对标内容全放 `structures[]` / `memories[]` / `reference{}`。

**为什么句式进了方法库**：`____元的____，我卖掉了____！` 这类是填空模板，属于「怎么写」，方法库本就收这样东西。方法库的四个分类是「选题方法 / 标题方法 / 开头方法 / 内容结构」——**只收写单条内容的技法**，账号级运营打法（平台分工、产品取舍、复制分级）不是这个形状，别硬塞。

**导入器的保险**：`kind: insight` 且没声明 `unit_type`（QST/CON/OPI/CAS/SOL）的原子会被退回并打提示，因为素材库按认知角色取料、角色为空就是取不到的死料，而素材库没有改角色的入口（`/api/materials/:id` 只有 DELETE）。导入结束会打印「退回 N 条」，不回退也不失败。

## 2026-09-17 · 按检查意见改写这一条

人设检查或质量门没过时，检查栏有「按检查意见改写」：把字数、设问开头、咨询腔、编客户这些问题直接拿去重写这一条。开头句槽位、来源引用、档案里的长句短词，改写管不了，还是要你点。空检查或只有槽位问题会 422，不改库。

质量门没过会把草稿标成要改。检查栏写成「要改」；改写成功后是「内容已就绪」。左侧列表同一套说法，不再露出内部英文 `needs_revision`。

检查栏按钮以前在「没能改正文的意见、正文改过还没再查、有未保存改动」时是灰的，点了没反应。现在按钮能点：没保存、检查过期、只有槽位问题，红字写在按钮下面；真正改写时显示「改写中...」。

`POST /api/drafts/:id/revise` 在旧 API 进程上会落到「接口不存在」。前端改成「后台还是旧版本，关掉窗口重新打开后再试。」页面热更新不会带上 Node。

以前检查意见塞进 JSON 的 note 字段，模型只看见「改短」，就把稿子写成更简单的一版。现在用户消息逐条列出字数、设问、咨询腔、编客户，并写明保留原判断、不要另写一篇更简单的。咨询腔会点名要删的词。

**但计划里那条验收——「拿真稿跑逻辑检查，必须指到『会不会得罪人』」——实测不成立**。

| 实测发现 | 具体 |
|---|---|
| **验收标准本身写错了** | 同一段正文、同一提示词跑 6 次：0 条 2 次、指到目标句 3 次、指到别句 1 次。**命中 3/6**。温度 0.7，它本来就会变——不能把概率事件写成「必须」 |
| **另一类假阴性** | 模型「确实没报」时 `status: passed`，界面仍然显示「已通过」——与上一轮修的「解析失败」不同，**这次没有 parser 可以怪** |
| **误报一例** | 说正文没解释「为何拆解完还是做不起来」，而正文下一句就是答案 |
| **引用闸门偏弱** | 闸门只查「这几个字在正文里出现过且 ≥4 字」，实测 4 字的「为什么？」也过关，标记会挂在这种词上 |
| **承诺与实测不符** | 无素材条件下模型编了 3 处（「我们复盘过大量IP账号」「我身边有个创业者」「文案改四遍」），质量门一条都没标，`evidence` 维度还给 100 分。根因：检测器一直在，**词汇表不含「创业者 / 复盘过X账号 / 改N遍」** |
| **误杀，且挡住发布** | 「第一反**应**」被判成广告法极限词「第一」→ 质量门 `blocked`、工作流进 `needs_revision`。规则已排除列表用法「第一，」，就是没排「第一反应」 |

**产出**

- `docs/audits/2026-09-20-full-audit/README.md`：本轮审计的**汇总件**（P1 8 条 / P2 4 条，每条落到「改哪个文件、怎么验收」）。
- 审计报告 25.6、25.8 两节补完；`.monkeycode` 计划里 25.6 / 25.8 / 25.9 标完成。

**本轮学到的三条**

1. **验收标准写「必须指到某句」在概率模型上是无效标准**。要写就写「跑 N 次命中率不低于某值」，
   或者把不确定本身当成要展示的信息（「模型本次未报出问题」不能等同于「没问题」）。
2. **模型不听话时，唯一的兵是确定性的检测器**。而检测器不会自己变宽——
   **每遇到一次真实编造，就应该把那个说法补进词表**，否则它就是一句安慰。
3. **误杀也是事故**。极限词的排除集已经修过一次（为此还写进了注释），
   同一条规则的另一种写法（「第一反应」）仍然绕过了它——**规则写的是词，用户写的是句子**。

## 2026-09-20 · 把审计里四条确定性缺陷修了（真模型实测那一轮的后半场）

作者：Monkeycode。

**做了什么**：上午把 25.6 真模型跑完，下午按审计里排的优先级，把**改法明确、能马上加断言的四条**修掉：

| 修了什么 | 为什么 | 断言（都是先反证、再修） |
|---|---|---|
| 「第一反应」不再当广告法极限词 | 真模型实测：一篇正常稿子因此 `blocked`、工作流进 `needs_revision`，**直接挡发布** | 断言写在 `server/draft-checks.test.mjs`；同时钉住「全网第一」「…是第一」仍然 blocked |

**顺带改的**：引句太短 / 整段拄的被丢弃时**单独计数并告知**（原来混在「只显示前 N 条」里，说不清为什么丢）；
逻辑检查提示词加了一条实测误报的反例。

**产出与验证**：`npm run verify` 全绿（测试 421 → 426，typecheck、build 通过）。

**本轮学到的两条**

1. **误杀也是事故**：极限词那条规则的注释里早就写着「序数、固定词要排除」——
   它排了「第一，」「第一步」，就是没排「第一反应」。**规则写的是词，用户写的是句子**；
   所以这次把「每遇到一次真实误报就把那个后续字补进来，并补一条断言」写进了代码注释。
2. **改「一类」而不是改「一例」**：四条里三条都是「词表 / 阈值不够」，
   而它们能存在，是因为**没有一条断言拿真实见过的句子盯着它**。真模型跑出来的原文就是最好的测试夹具。
