# 任务决策记录

> **2026-09-03，Task 5 人工确认采用专用接口与原子拍摄衔接**
> **决定了什么：** 使用 `POST /api/drafts/:id/approve` 和 `POST /api/drafts/:id/revoke-approval`；确认时保存当前草稿版本与检查深拷贝，并按 `owner_id + draft_id` 幂等创建或复用拍摄项。
> **为什么：** 避免通用草稿更新绕过质量门，也避免确认成功但拍摄项未创建的中间状态；同时保留确认、撤回、来源和发布历史。
> **排除了什么：** 排除通过通用 `PUT /api/drafts/:id` 写入确认、分开执行确认与拍摄创建、从草稿状态动态派生拍摄清单。

> **2026-09-03，已确认内容修改后必须重新检查与确认**
> **决定了什么：** 标题、正文、平台、来源、Hook 或事实核验状态变化会使确认失效并将关联拍摄项置为 `needs_revision`；已确认草稿需先撤回才能重跑检查、重生成 Hook 或恢复历史版本。
> **为什么：** 防止旧版本检查和确认快照覆盖新内容，确保进入拍摄的正文与确认版本一致。
> **排除了什么：** 排除继续沿用旧确认、允许客户端直接覆盖检查快照或工作流状态。

> **2026-09-03，Task 6 采用只补审计证据、不改运行时的质量门方案**
> **决定了什么：** 通过旧 JSON 启动兼容、MySQL 嵌套字段往返、接口账号隔离、全链路来源、合成敏感字段、状态边界及完整构建验证完成第一阶段审计；未发现需修复的运行时缺陷。
> **为什么：** 任务 1–5 的现有实现符合已批准业务含义，新增测试已覆盖原先缺少的跨层证据，继续修改运行时代码会扩大范围和回归风险。
> **排除了什么：** 排除浏览器自动连接、自动发布、全量 Easel Skill 移植、新运行时模块、依赖和无关重构。
