# 旧规划复审：用自媒体专家视角重看 `content-workbench-upgrade`

复审日期：2026-09-19
复审人：Monkeycode
复审对象：`content-workbench-upgrade`（DBS 内核路线，19 组任务，已完成 17 组）
复审身份：**自媒体操盘手 / 内容专家**（不是工程视角）

## 为什么要复审

这份规划写于我还在**工程视角**时。当时的判断标准是"技术上正确、架构上自洽"。现在的判断标准只有一条：

> **它能不能帮创作者把号做起来、赚到钱。**

按新标准重读，19 组里有 **3 处该撤、5 处该改、2 处该砍、1 处该提优先级**。下面逐条给证据。

---

## A. 该撤的（最急，因为现在系统在妨碍人）

### A1. 冷启动 422 拦停 —— 把最需要帮助的人挡在门外

**问题**：IP 档案缺 `role` / `audiences` / `pillars` 时，`POST /api/topics/generate` 直接返回 **422 `COLD_START`**（`server/cold-start.test.mjs:36-42`）。定位没填完，**就不让生成选题**。

**专家视角**：这是一个逻辑上的自相矛盾。

- 不知道自己该做什么号的人 → 定位填不出来 → 系统不让他生成选题 → **他永远开不了头**
- 而"不知道拍什么"恰恰是这些人**最大的问题**，也是最需要系统给方向的时候
- 真实路径是反过来的：**先发 20 条乱的，才慢慢知道自己是什么号**。定位是发出来的，不是想出来的

**怎么改**：
- `COLD_START` 从 **422 拦停**改成 **200 照常生成 + 一句提示**（"定位还没填，这 3 个选题会比较泛；填完定位会更准"）
- 保留 `missing_fields` / `gain` / `paths` 三个字段的信息量，但**作为提示返回，不作为拒绝理由**
- 依据：README 第 0 节"不能因为创作者还没录入而拦住他"

**证据**：`server/cold-start.test.mjs:36-42`、`server/guide.mjs:12-24`（定位排在第 1 段）

---

### A2. 「不可溯源数字 / 案例」拦停生成

**问题**：阶段 13.2 新增闸门——案例位或数字位使用了不可溯源素材时**拦停生成**；阶段 9.2 的 `derived` 素材不进简报案例位。

**专家视角**：**这正是 Alex 上一轮明确否掉的那件事。** 我当时的原始设计是"数字和案例必须挂真实来源，否则不许生成"，Alex 的原话是：

> "你不可能让一个人把所有的数据全部都喂给你。很多数据或选题，是他做完之后复盘，或者在某个场合突然想起来的。你只能在最后加个提醒，让他自己去确认。"

而这份规划把它做成了**生成前的闸门**。

**怎么改**：
- 撤回 13.2 的这条闸门，**跟 13.3 的 `length_severe` 一样降为提醒**
- 提醒位置挪到**发布前**，一句话，同行口吻："这条里有个数字，评论区一定会问哪来的——你答得上来就行，不用录进系统。"
- 9.2 的 `derived` 过滤：**从"不得使用"改成"用了要标"**

**证据**：旧规划 13.2「新增：案例位或数字位使用了不可溯源的素材」、9.2「derived 不得用于案例位与数字位」；对照 `README.md` 第 0 节

### A3. 选题把关的 `blocked: true` 否决权

**问题**：阶段 8.2 的五维 / 七维把关，全不通过时返回 `blocked: true` + 「不建议做」。

**专家视角**：

- 「不建议做」可以，**`blocked` 不行**。这中间差的是一件事：**创作者可能就是要做，因为他知道自己的观众，而系统不知道。**
- 而且**相当一部分爆款恰恰来自"看起来不该做"的选题**。用一套固定维度去否决，是在用一个通用模型覆盖创作者的现场判断。
- 一个做了二十年号的人，不会因为系统打了低分就不拍；他只会**从此不再看那个分数**。

**怎么改**：
- `blocked: true` 字段去掉，改成 `advice`（一句话建议 + 一个改法）
- 维度保留在后台作为检查依据，**前台只给一句话判断**

**证据**：旧规划 8.2「五维全不通过时返回明确的『不建议做』并带 `blocked: true`」；`server/data.json` 里已有大量 `"status": "blocked"` / `"severity": "blocked"` 的历史记录，说明这个概念已经渗透进质量门

## B. 该改的

### B1. `material_trust` 三档：从「取料闸门」改成「参考资料」

**问题**：`verified` / `sourced` / `derived` 三档，且"客户端不能自封可信度——上传体里的 `material_trust` 被忽略"。

**专家视角**：

- **`verified` 是审计词，不是创作词。** 创作者不关心"这条核实过没有"，他关心"这条能用在哪"。而且**"真不真"只有他自己知道**——系统凭什么替他判
- "上传落 `verified`"这个默认值站不住：上传的东西是**用户自报**的，不是核实过的。用 `verified` 命名，等于系统替用户背书
- 三档作为**提示**有价值（"这条是模型生成的，你自己看一眼"）；作为**取料闸门**价值为负（因为它拦住的正是"他记得但没录来源"的料）

**怎么改**：
- 保留三档数据字段，**改用途**：从"过滤条件"改成"列表上的一行小字"
- 语义措辞改掉：`verified` → 自报 / `sourced` → 有来源 / `derived` → 模型生成
- **不再有"某档不得进案例位"的规则**；改成"用了模型生成的料，发布前提醒一句"

**证据**：旧规划 3.1「客户端不能自封可信度」、9.2 的过滤落点 `briefUsableMaterial`

---

### B2. 七维（五维）评估报告：压成一句话

**问题**：阶段 8.2 实际做成了**七维**评估，返回五个维度各自结论 + 一句话总结 + "如果要做第一步是什么"（旧规划 8.2 回填）。

**专家视角**：

- 创作者决定"这条要不要做"，脑子里只有两个问题：**有人在乎吗？我说得出来吗？**
- 给他七维打分，他**会看第一次，第二次就不看了**
- 更要紧的是：**分数会把判断责任从他身上拿走**。而做号这件事，判断权必须在他手上——那是他唯一比系统强的地方
- 七维报告是**工程师的完整性**，不是**创作者的决策效率**

**怎么改**：
- 后台维度一个不减（诊断精度要保留）
- **前台压成两句话**：「这条我建议做 / 别做」+「要做的话，第一步是 X」
- 详细七维折叠在"看细节"里，默认收起

**证据**：旧规划 8.2 回填「选题评估走 `evaluateTopic`，**七维**（测试写明不因『五维诊断』砍掉制作成本和合规风险）」

---

### B3. 11 段链路：前 4 段从「步骤」改成「随手可补的资产」

**问题**：阶段 17.2 的链路是 **定位 → 素材 → 对标 → 结构库 → 选题 → 初稿 → …**，共 11 段。

**专家视角（本次复审最重要的一条结构意见）**：

- 这 11 段的顺序是**建库顺序**，不是**创作顺序**
- 前 4 段（定位、素材、对标、结构库）全是**准备工作**。排在"选题"前面，等于**告诉新手"你要先建完库才能开始做内容"**
- 而真实情况是：一个创作者今晚坐下来，脑子里是"我今天刷到个东西，特有感触"。**他不需要先有对标库**
- 结果就是：**新手卡在第 1 段，永远走不到第 5 段。**

**怎么改**：
- 主线从**第 5 段「选题」开始**：选题 → 初稿 → 诊断改稿 → 定稿 → 拍摄 → 发布 → 回流
- 前 4 段移出主线，改成"随时可补的资产"，在需要它的那一步被叫出来（例：选角度时叫定位，撑中段时叫素材库，做开头时叫结构库）
- **不删任何一段**，只改它出现的位置

**证据**：旧规划 17.2、`server/guide.mjs:12-24`

### B4. 标题公式库：前台一次只给 3 个方案

**问题**：阶段 14.1 抄全了 **75 条**小红书标题公式（抖音与视频号各一份），14.3 输出多个方案供选择、每个可溯源到公式编号。

**专家视角**：

- **75 条是数量上的勤奋，不是有效性的勤奋。** 而且这份库明说"举例全为小红书原例并标清来源，不编造平台版"——**小红书标题是"搜索词 + 情绪"，抖音口播标题是"钩子"，两者不是一套东西**。把 75 条小红书公式摆在抖音创作者面前，大部分不适用
- 更实际的问题：**给创作者 75 个选项等于没给。** 他要知道的是"这一条该用哪个"，不是"有 75 种可能"
- 一个操盘手给标题，从来不给人选，**他直接给三个，并说清为什么是这三个**

**怎么改**：
- 75 条保留作为后台弹药
- 前台**一次只出 3 个方案**，每个附一句"为什么给你这个"
- 抖音/视频号的公式库要**真正重写**，不能拿小红书原例充数

**证据**：旧规划 14.1、14.3

### B5. 语言层 22 特征：降级为可选层，把「开头 3 秒」提到主角

**问题**：阶段 12 建了 22 个语言特征 × 追问，是诊断层里最重的一块。

**专家视角**：

- 12.4 的措辞校准（"不以『去 AI 味』为目标表述；目标是让用户看清自己的文字"）**方向完全对**，写这版的人想清楚了
- 但**22 个特征这套框架本身，仍然是 AI 味检测的框架**。而创作者的真实目标是"这条能不能爆"——**爆不爆主要由开头 3 秒和选题决定，不由语言细节决定**
- 所以现在的权重是倒的：**最容易决定成败的开头，和 22 个语言特征并列**；语言那层反而更重

**怎么改**：
- 语言层保留，但**降级为可选的一层**（用户主动点开才展开）
- **把 14.2 的开头多维诊断（dbs-hook）提到诊断的主角位**——它才是决定完播的那一环

**证据**：旧规划 12.1、12.4；对照 14.2

## D. 该提优先级的

### D1. 阶段 11「标记式改稿」——它是唯一未完成的核心环节

**问题**：19 组里唯一未勾选的核心项，理由是"不在 918 收官八项范围内"。

**怎么改**：把阶段 11 从"保持未勾选"提到**高优先级**，位置排在配比通电之后。

**证据**：旧规划 11（唯一未勾选的核心项）、10.5

## F. 一处现实风险（不是错，是会白做）

### 回流依赖「用户手动确认表现数据」→ 决定了它基本不会被用

16.2 只认 `status: 'confirmed'` 的快照。而**创作者不会手动录入表现数据**——发布完他就去拍下一条了。

**后果**：这一段链路设计得对，但会因为没人喂数据而**长期空转**。16.2 的"影响下一轮选题"永远不会发生。

**怎么改**：把录入压到最少——**只让他填两个数：播放量、涨粉数**。其余（完播、互动）能自动拉就拉，拉不到就不显示，别让他填。

## 复审结论

旧规划**不是白做的**——19 组里 13 组明确该留，诊断层尤其扎实。问题集中在**三类**：

1. **拦停太多**（A1/A2/A3）——与"不设卡"的角色直接冲突，最急
2. **前台太重**（B2/B4/B5）——后台做得比前台需要的多，需要减负
3. **顺序反了**（B3）——建库顺序当成创作顺序，把新手挡在门外

这 3 类整改，加上上游取材（配比通电 / 素材分池 / 选题入口）和未完成的标记式改稿，合并成新的分期方案，见 `.monkeycode/specs/ratio-driven-intake/README.md`。

## 复审更正（2026-09-19，动手实现阶段 0 时发现）

下面两条是上面这份复审**自己写错了**。动手核对代码后更正，不改上文，方便对照。

### 更正 1：B1（`material_trust`）的判断不成立，这一项不做

**上文原来写的**：「三档作为取料闸门价值为负（因为它拦住的正是『他记得但没录来源』的料）」。

**核对代码后的实情**：

- 三档的实际定义（`validation.mjs:62-65`）：`verified` = 自己确认过的（手动新建 / 上传）；`sourced` = 外部采来的（火狐采集）；`derived` = **模型生成的、未经核实**。
- **没录来源的历史素材默认按 `verified` 读**，根本不会落到 `derived`。所以我说的「拦住他记得但没录来源的料」**不成立**。
- **全项目没有任何一处代码写过 `derived`**（唯一的写入点是 `followup-answers.mjs:38` 的 `verified`）。也就是说 `briefUsableMaterial` 这个过滤器**是死代码，永远不会触发**。
- 最要紧的：它过滤的是**喂给模型的提示词**（`draft-writing.mjs:161-164`、`:173`、`:192-193`），**不是拦用户**。用户没有任何操作被挡住，跟那三道 422 不是一类东西。
- 而且它的意图是对的：不让模型推出来的细节被当成事实写进正文。

**结论：这一项不做。** 真正还成立的部分只剩**措辞**（`verified` 这个词是审计词），而那是界面文案问题，归阶段 2/3，不是代码封锁问题。

### 更正 2：我把「命中风险词」分错了类，它必须继续拦

**上文性质那一节的表里**，我把「命中风险词」归进了「不该拦」。**这是错的。**

风险词是「第一 / 最好 / 100% / 根治 / 包赚 / 稳赚」这类**广告法红线**，发出去是账号要挨罚的。它属于「机械事实」那一栏里最硬的一条——**法律不因为「这是你的判断」就不罚你**。

### 实做时的最终分寸（比上文那张表更准）

| 继续拦 | 降为可改项 |
|---|---|
| **正文为空**（空稿没法拍） | **综合分低于 60**（分数是系统的看法） |
| **命中风险词**（法律红线） | **缺来源引用**（你心里有数就行） |
| | **没选开头范式**（这是逼你用功能，不是稿子有问题） |

已按此改 `draft-checks.mjs`。同时发现并修掉一个被这个改动暴露出来的真 bug：`draftCheckRewriteNote` 原来用「整体状态是不是 passed」决定要不要抽改写指令，于是**「整体通过但字数超了」时，改写指令里反而没有字数要求**。改成不看整体状态。
