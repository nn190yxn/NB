## 简介

把「定位派」个人 IP 内容工作台从「生成成品 → 验收成品」改成「给一个初稿 → 陪用户改」。诊断全部按 DBS（dontbesilent）开源技能共用的**五步形态**重建：接收 → 分维度诊断 → 出报告 → **问要不要改** → 确认后标记式改稿。内容层从「生成后审查」前移成「生成前取材」。平台从 4 个收敛到抖音 + 视频号。

## 核心结论（三条）

1. **判据不再由我们发明。** 它有两个来源：DBS 的可溯源内核，与用户自己的终稿回流。现状的根本矛盾不是规则写得不好，是**判据用错了对象**——初稿被当成成品验收。
2. **内容层是「取材层」，不是审查层。** 它在生成之前落地。这一步顺带解决编造问题：模型编客户和数字，是因为简报里没有真素材。素材加了可信度三档后，「案例位能否溯源」成为**客观**判据。
3. **语言层不做归并、不设数量上限。** DBS 的 `dbs-ai-check` 有 22 个特征且不矛盾，因为每条都配「背后意图 + 追问」。真正防清单爆炸的机制是**一次只呈现一条 + 按文本顺序**。
