# 检查点记录（任务清单 18.1）

按规格要求，在阶段 3 与阶段 10 完成后各设一个停止点，确认设计没走偏再继续。这里记的是**事后按证据回填**的核查，不是当时的会议纪要——检查点本应在当时做，这一项是我在收尾时补的，如实说明。

## 检查点一：阶段 3 之后（判据分层与素材信任）

**该停一下的理由**：阶段 3 引入 `material_trust` 与「不可溯源素材闸门」，直接决定后面所有诊断拿什么当尺子。如果这一步把「我们发明的规则」当成判据，后面全歪。

**核查结论：没走偏。** 证据：

- 信任分层是数据字段（`material_trust` / `unit_type`）＋ 闸门，不是新的规则表；老记录缺失该字段时走默认值（`legacy JSON workflow records receive safe defaults and remain operable` 通过）。
- 不可溯源素材在源头被拦，不是靠事后审查（`阶段 13.2 剩余：不可溯源素材闸门` 已交付）。
- 没出现「系统自己发明判据」的路径：所有拦截点都能追到用户素材或 dbs 源技能。

**当时若发现偏差应做的动作**：把规则表退回到「只做结构层闸门」。

## 检查点二：阶段 10 之后（语言层 22 特征与诊断报告）

**该停一下的理由**：阶段 10 把 dbs-ai-check 的 22 个特征搬进来。这一步最容易出的偏差是「把审美类提醒做成拦停」，那会让工作台退回到「生成成品 → 验收成品」的老路。

**核查结论：没走偏。** 证据：

- 22 个特征骨架照抄源技能，编号 1–22 不重不漏（`22 个特征骨架照搬 dbs-ai-check` 通过）。
- 语言层提醒不拦停、不触发自动重写、不影响 `workflow_status`（`发布前报告只拦停发布` 相关的非拦停断言通过）；发布前共鸣报告同样只出报告（`发布前报告只出报告，不拦停发布` 通过）。
- 判据来源有两条且都能回溯：dbs 内核 + 用户终稿回流（回流候选默认 `pending`，确认才生效，`回流候选要用户确认才生效，确认过程不碰草稿` 通过）。
- 已知未完成：22 个特征里 14 个还没有检测器，代码里明确记为「宁可空着，不硬凑对应关系」；语言层判据由回流产出**替换**目前只做到「可查替换清单」，诊断侧还没主动跳过已替换特征。这两条不算偏差，属于未完工。

**当时若发现偏差应做的动作**：把语言层从「检查项」降级为「提醒项」，并去掉任何自动重写路径。

## 这两个检查点之后仍然有效的原则

1. 结构层可以拦停，语言层只提醒。
2. 判据必须有来源，来源要么是 dbs 源技能，要么是用户自己的终稿。
3. 凡是「系统替用户下结论」的地方，都要改成候选 + 用户确认。
