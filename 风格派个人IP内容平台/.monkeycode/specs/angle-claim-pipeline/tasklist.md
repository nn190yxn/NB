## M2 的实机验收脚本（用户在界面上自己走，不需要读代码）

1. 素材库确认没有同文多条（批次 1）。
2. 红狐搜「西贝 关店」，选一条「以此立选题」，角度「经营」（批次 3）。
3. 「提主张」跑一对角度「老板 / 员工」，两组主张分别逐条勾选入库（批次 2）。
4. 对其中一条点「查逻辑」，故意改成站不住的写法，确认它标灰但仍能被选去生成（批次 2）。
5. 立选题：主观点指向第 3 步存下的主张，角度「经营」（批次 3）。
6. 生成草稿 → 打开简报：`stance` 是选的观点、`material_roles.OPI` 非空、反方里能看到老板与员工两组主张（批次 3）。
7. 正文里每个案例和数字都能回到素材库找到那条素材（批次 3）。
8. 转口播后检查仍带结果，不是"已清空"（批次 4）。
9. 定稿 → 拍摄 → 发布 → 回填一次数据 → 回流候选确认一条，`preferences` 不再为 0（链路末端）。

任一步不满足，就是对应批次的缺陷，不需要重新猜。

## 实施记录（2026-09-21，批次 0–5 + 6.1/6.3/6.4）

全量口径：`npm test` 481 项全绿（起点 445，新增 36 项），`tsc -b` 与 `vite build` 通过，`check-live` 退出码 0。

1. **批次 0 的两层防线都实测过**：无 `--watch` 时改一个源码文件 → `check-live` 退出码 1 并说「磁盘上的后台代码比正在跑的进程新」；换 `npm run server:watch` 后自动重启、退出码回 0。踩到一个真问题：仓库在中文路径下，`git status --porcelain` 会把路径转义成八进制加引号，前缀比对全失配，`dirty` 因此漏报——改用 `-z` NUL 分隔后正确。
2. **`/healthz` 没加字段**：它的返回形状被 `auth.test.mjs` 用 `deepStrictEqual` 锁着（监控契约），版本信息只走 `/api/version`。启动器改读 `/api/version` 判陈旧。
3. **素材身份的落地方式**：`server/material-key.mjs` 一份实现，五条入库路径共用；`return-flow.mjs` 原来的私有 `normalize()` 改成引用同一份，不留第二把尺子。文件级哈希降级成 `source_checksum` + 一条来源引用，桌面同步的队列哈希不受影响。
4. **内容策略两个接口和 `generate-keywords` 决定不删**：查过前端与桌面端，三者都没有调用方，但 `reviews`/`recommend` 返回的是 `insufficient_data` + 一句人话理由（README 第 0 节也是这么记的），属于"如实说没数据"而不是伪装结论；删它们要连带动账号隔离测试的覆盖面，收益不抵改动。留原样，登记在此。
5. **研究条目的"分析"改成真调用**：原来不管收到什么都返回同一份写死的拆解（连置信度都固定），现改由模型看这条热点产出（`server/research-analysis.mjs`），没配模型直接 422；提示词里明写"信息少就给低置信度，不要一律给高分"。
6. **一处口径变更**：`generation-test-helper.mjs` 的 mock 现在会按提示词里那对角度给主张打角度标签，并为「口播方法拆解」按条目出结果——mock 若还像旧实现那样返回固定值，测试就是在测一个已经不存在的行为。
7. **测试稳定性**：新增的四个测试文件最初每个用例各起一个后台，并发跑全套时会有文件卡在 5 秒启动超时上（表现为整文件失败、且每次换个文件挂）。改成**一个文件共用一个后台 + 文件级 after 钩子关进程**后，连跑三次 477 全绿。

8. **那处「偶发的整文件失败」后来查清了，不是偶发**（本条已由 13–18 的走查复核并改写）：能稳定复现的那一次，原因是**测试文件要在仓库根目录跑**——62 个文件用 `cwd: process.cwd()` 起后台、入口写成相对路径 `server/index.mjs`，在 `server/` 目录里单跑就变成「路径不存在 → 后台退码 1 → 测试只剩一句『异常退出: 1』」。同一轮里 5 秒启动超时（37 个文件各抄一份）也确实会造成并发下的整文件失败，那条通过端口锁 + 超时对齐到 20 秒解决：`npm test` 单跑两次 + 并行双开两套全部绿、零异常退出。**没有为了压住失败而调参数**。剩下的收尾见 19 条。

9. **3.9 / 6.2 已做完：把 M2 脚本自动化成 `scripts/verify-m2.mjs`**（加 `--run` 才调模型；跑之前复制一份 `server/data.json` 到临时目录，绝不碰真实数据）。连跑七轮，最后一轮 **18/19 步通过**。真模型复验又抓到三件自动化测试抓不到的事：
   - **`parseClaims` 把「这个角度提不出不同说法」当错误抛** → 接口 502。反驳式提问本来就该允许某个角度交白卷，现在只有「提到了主张却没给核心判断」才报错。
   - **数据回流候选恒为 0 的真因**：`performanceCandidates` 只认英文 `metrics.views`，而界面回填的是中文键（`播放量`）。这条断的就是闭环最后一段——真实数据里 `preferences` 一直是 0 条就是这么来的。现在统一走 `growth.mjs` 那把指标匹配口径，并补了中文键的回归测试。
   - **成语被当成编造数字**：模型在正文里写「十万八千里」，不可溯源数字闸门把它标了出来。加了成语词表（明确不用「含两个数量级词就算成语」的通用规则，因为「一百三十」「三万五千」是正常数字写法，会被误杀）。
   - 顺带发现：**上游模型没有备援时，502 会随机复现**（七轮里两轮撞上游失败，撞的还不是同一步）。验收脚本因此把「上游故障」与「链路缺陷」分开统计并重试，避免下一次有人去改本来没坏的代码。**建议：在 API 中心给 `text_fallback` 也配一个模型**，这是目前最容易造成"看起来又坏了"的原因。
   - 唯一没通过的一步（反方为空）不是断线：那轮模型只在「老板」角度提出了主张。已把它变成界面上看得见的信息——某个角度没提出不同说法时，主张面板会明说「这条素材里没有它的立场差」，而不是悄悄给你一条没有反方的稿子。

10. **补上一处「后端有、界面没有」的缺口（Requirement 8.1 与 3.1 的最后一公里）**：`PUT /api/topics/:id/stance`（改角度、指定主观点）和素材的角度 / 认知角色编辑，接口都通了但界面上没有任何入口——对一个不写代码的用户，没有入口就等于没有这个功能。补了：
